This plan documents the first leakage-safe evaluation pass between
Phase 8 OOF model PMFs and Odds API historical player-prop market data.
It is intentionally a **single-day proof**, not a full backfill.

## Capture command (per-event historical lock)

```
python3 scripts/oddsapi_nba_props.py historical-lock-day \
    --target-date 2026-03-31 \
    --max-events 2 \
    --commence-after 2026-03-31T00:00:00Z \
    --commence-before 2026-04-01T06:00:00Z \
    --lock-offset-minutes 5
```

Behavior:

1. Fetch historical events list once at `{TARGET_DATE}T11:00:00Z`
   (≈07:00 ET; all games scheduled that day are still upcoming).
2. Filter to commence-window if specified.
3. For each of the first `--max-events` events (sorted ascending by
   commence_time):
   - Compute `snap = commence_time_utc − {lock-offset-minutes} minutes`.
   - Assert `snap ≤ commence_time_utc` (leakage guard).
   - Fetch `/v4/historical/sports/basketball_nba/events/{event_id}/odds?date={snap}`
     with all 10 player-prop markets.
4. Save raw JSON + processed quote/pair parquet+csv with
   `snapshot_type = historical_lock_minus_5m`.

Cost (approx): 1 historical events list (~10 credits) + 2 historical
event-odds (~100 credits each) ≈ **~210 credits per 2-event proof day**.

## Evaluation command

```
python3 scripts/evaluate_oof_vs_oddsapi_market.py --target-date 2026-03-31
```

Steps:

1. Load OOF rows for `target_date`.
2. Load `oof_market_match_manifest` filtered to that date.
3. Load all `odds_pairs_*.parquet` under `data/odds_api/processed/{target_date}/`.
4. **Leakage filter**: drop any pair row with `snapshot_time_utc > commence_time_utc`.
5. Normalize player names (NFKD-fold, lowercase, strip diacritics, drop suffixes).
6. Inner-join on `(player_name_norm, market_stat)` against the OOF universe
   for that date.
7. Per matched row, compute `model_p_over_line` from the OOF `pmf_active`
   (or `pmf` fallback) at the offered `line`.
8. Compute `over_realized = (outcome > line)`, `is_push = (line == int(outcome))`.
9. Score (excluding pushes): logloss + Brier of model vs no-vig market.
10. Stratify by stat and book.
11. Alternate-line ladder: per
    `(player × stat × book × snapshot_time_utc)` group with ≥ 2 lines,
    compute mean `|model_p_over_line − no_vig_over_prob|`.

## Leakage safeguards

- The capture script computes `snap = commence_time - lock_offset_minutes`
  and refuses to call the API if `snap > commence_time` (impossible by
  construction; defensive assert).
- The evaluator drops any pair row where `snapshot_time_utc > commence_time_utc`
  before scoring; the dropped count is reported.
- The OOF outcome is the post-game realized stat (not used for any pre-tip
  feature); the model PMF was generated by the Phase 8 walk-forward without
  seeing post-fold outcomes. Standard CLV grading is **not** included in this
  one-day proof — that requires opening + closing snapshot pairs and is the
  next phase.

## Honest expectations

- The full-OOF matched audit (n=3,818) found the de-vigged closing market
  beats the standalone calibrated model on log-loss in 9 of 11 cohorts at
  95% CI.
- A one-day proof with ~30 matched rows is **far too small** to draw any
  market-beating conclusion. The goal is to:
  1. Prove the capture → match → score pipeline runs end-to-end.
  2. Surface name-normalization / stat-mapping mismatches early.
  3. Establish the alternate-line-ladder evaluation skeleton for the
     full backfill.

## Scaling roadmap (out of scope for Phase 9B)

1. After the 2-event proof passes, expand to a full single-day capture
   (`--max-events 12`).
2. Once that runs cleanly, scale to a 7-day rolling window of recent OOF
   dates and produce a stratified eval (by stat × role_bucket × book × line bucket).
3. Then, run the full 2024-10-23 → 2026-03-31 historical backfill over
   multiple billing periods (≈ 1.25M historical credits); commit results
   into `artifacts/phase9_market_eval/full_oof/`.
4. Re-run the matched-closing-line audit using the full-OOF results
   produced in step 3 — these become the authoritative "model vs market"
   numbers for the project.
